## 日常只改三个开关

每条内容开头均为：

```text
应用标识：com.xxtstudio.accountDL
应用开关：开
弹窗开关：开
信息流开关：开
```

- 停用该应用：把 `应用开关` 改为 `关`，弹窗和信息流都关闭。
- 只展示帖子：应用开关 `开`、弹窗开关 `关`、信息流开关 `开`。
- 只展示弹窗：应用开关 `开`、弹窗开关 `开`、信息流开关 `关`。
- 切换应用：先关闭原应用的应用开关，再打开目标应用的应用开关。若同时打开多款，客户端可读取多款，显示数量仍受全局数量限制。

修改后点击「确定」保存。`应用标识` 是稳定身份，请勿改成其他应用，也不要把优先级改成普通公告。

## 一条记录包含该应用全部素材

同一条内维护应用名称、小注释、多行介绍、官方图标、应用市场链接、免提醒文案，以及信息流的昵称、账号、头像、正文、手机媒体和平板媒体。新客户端的弹窗与帖子共用本条的 `应用链接`，不会借用其他应用的图标、文案或媒体。

`弹窗提醒：普通` 表示普通推荐，可改为 `强制提醒`。三天免提醒按应用分别保存，切换到另一款应用不会沿用上一款的免提醒。

末尾的 `帖子开关` 和 `帖子链接` 保留给旧客户端兼容。当前客户端以开头的三个开关和 `应用链接` 为准；若需要让旧版信息流也跟随切换，同时把末尾 `帖子开关` 与「应用开关且信息流开关」的结果保持一致。

## 变量配置只管全局

| 变量 | 当前值 | 作用 |
| --- | --- | --- |
| `harmonyx_enabled` | `on` | 所有推广内容的总开关 |
| `harmonyx_recommend` | `on` | 全部应用推荐的总开关，不选择具体应用 |
| `harmonyx_popup` | `{"splash_enabled":true,"splash_daily_limit":0,"splash_interval_hours":0}` | 每次打开均允许展示一轮开屏 |
| `harmonyx_post_count` | `1` | 时间线推荐帖数量 |
| `harmonyx_post_comment_count` | `1` | 评论区推荐帖数量 |
| `harmonyx_post_revision` | `2` | 推荐帖免提醒的版本标记 |

具体推荐哪款应用，在公告配置的 `【推荐应用】` 条目里控制。`harmonyx_popup` 是旧版兼容配置，不再用它指定应用名称和图标。

## 评论随机展示与弹窗时段（2026-10-26 客户端）

评论区每次新进入详情页独立抽取，默认有 30% 概率展示推荐帖；未抽中时不插入。
抽中后随机选择应用和前几个顶层评论之间的位置，本次浏览以评论 ID 固定位置，
重绘、点赞和加载更多都不会重新抽取，也不会拆开父子回复。退出后再次进入会重新抽取。
图片、视频内嵌评论页继续不插入推荐。时间线和搜索结果的推荐位置也随启动随机变化，
同一次启动保持稳定。

自动推荐弹窗默认按设备本地时间分为 00–06、06–12、12–18、18–24 四个时段，
同一时段所有推荐应用合计最多展示一次，关闭应用后再次打开也会保留记录。
云端未设置次数和间隔时，客户端默认每天最多 2 次、每次启动最多 1 次、最少间隔 6 小时。
已有云端限制继续叠加，例如 `daily_limit=1`、`interval_hours=24` 会更严格地限制展示。
强制提醒也不能绕过时段、次数或间隔，普通公告和版本更新沿用各自的规则。

| 独立变量 | 客户端默认值 | 用途 |
| --- | --- | --- |
| `harmonyx_post_comment_probability` | `0.3` | 每次进入评论区的展示概率，范围 0–1；`0` 不展示，`1` 每次符合条件时展示 |
| `harmonyx_popup_period_hours` | `6` | 本地时段长度，取 1–24 的整数小时；每个时段最多一次自动推荐弹窗 |

这两个值也可写入 `harmonyx_popup` JSON 的 `post_comment_probability`、`popup_period_hours` 字段。
独立变量存在时覆盖同名 JSON 字段；缺失时使用上述客户端默认值。本次客户端改动不修改云端已有值。

## 推荐帖关闭限制与弹窗频率（2026-10-18）

这些变量需要包含本次联动代码的新客户端。旧安装不会识别新增控制项。当前
`harmonyx_enabled=on`，支持者免推荐资格仍然有效。

在同一软件的「变量配置」修改以下独立变量并保存。客户端在前台约每 60 秒刷新，返回前台也会检查；批量变量无法读取时暂停推荐，等待下一次成功刷新，避免丢失帖子锁定和次数限制。无需为改次数重新发布客户端。

| 变量名 | 预设 | 用途 |
| --- | --- | --- |
| `harmonyx_post_dismissible` | `off` | 推荐帖没有关闭和七天隐藏入口，也不沿用历史隐藏状态；改 `on` 恢复关闭能力 |
| `harmonyx_popup_force` | `on` | 忽略三天免提醒，仍受时间窗口、间隔和次数限制 |
| `harmonyx_popup_dismissible` | `on` | 可手动关闭；改 `off` 隐藏关闭及免提醒，成功打开「立即体验」目标后收起 |
| `harmonyx_popup_delay_seconds` | `5` | 首页允许展示后等待几秒，范围 0–3600；登录、引导等界面结束后计时 |
| `harmonyx_popup_interval_hours` | `24` | 两次弹窗的最小间隔小时，支持小数，`0` 不限 |
| `harmonyx_popup_daily_limit` | `1` | 每台安装在设备本地自然日内最多弹几次，`0` 不限 |
| `harmonyx_popup_total_limit` | `0` | 本活动每台安装累计最多弹几次，`0` 不限 |
| `harmonyx_popup_session_limit` | `1` | 每次启动最多弹几次，`0` 不限 |
| `harmonyx_popup_start_at` | `0` | 开始时间；`0` 立即有效，或 `2026-11-01T09:00:00+08:00` 这样的带时区时间 |
| `harmonyx_popup_end_at` | `0` | 结束时间；`0` 不设结束，到结束时刻停止自动弹出 |
| `harmonyx_popup_revision` | `1` | 活动版本；改为新整数重置本活动次数和间隔 |

次数是**当前安装的所有推荐应用合计**，并且只在自动弹窗实际展示时记一次；拉取配置、准备图标、被登录界面挡住、用户主动查看推荐均不计数。每天与累计次数、最近展示时间跨重启保存；卸载重装或清除应用数据后重新计数。时段限制、每日上限、累计上限、启动上限、最小间隔、开始/结束时间同时约束，强制提醒不会越过它们。后台普通公告、文章、Banner、版本更新不使用这套推荐次数。

常见调整：

- 每天最多 3 次：`daily_limit=3`、`session_limit=0`、`interval_hours=4`、`period_hours=4`（此处省略公共前缀 `harmonyx_popup_`）。
- 每次启动至多 1 次且每个时段至多 1 次：`daily_limit=0`、`session_limit=1`、`interval_hours=0`。
- 一个活动只弹 1 次：`total_limit=1`；以后需要新一轮再增大 `revision`。
- 只改上限就直接改对应变量；只有确实要重新计数才改 `revision`。将累计上限从 1 改为 3 会在原有计数基础上继续。
- 填错开始/结束时间或开始时间不早于结束时间时停止自动弹窗，防止错误配置意外投放。

总开关或应用开关关闭后仍会收起强制推荐弹窗；强制版本更新继续遵循独立的版本管理策略。

## 旧配置

`【旧配置已停用】` 开头的条目仅保留历史内容。不要用旧的「链接、提醒优先级、应用信息、应用图标、跳转链接、请您再考虑一下、推荐帖媒体、推荐帖二」选择推荐应用。

新客户端检测到任一应用配置后，仅按新配置展示。即使五款应用全部关闭，也不会回退到旧的印记内容。

整理前的原始公告备份保存在 `outputs/xxauth-app-catalog-before.json`；最终直连读取与解析结果保存在 `outputs/xxauth-app-catalog-verification.json`。
