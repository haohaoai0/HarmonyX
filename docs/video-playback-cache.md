## 播放链路

`SurfaceVideoPlayer` 优先读取已有完整 MP4；未缓存时向 `VideoRangeSource` 获取流租约，AVPlayer 播放它的 `127.0.0.1` 地址。首次 GET 只取 64 KB 文件头，同时取得大小，省去 HEAD；解析器先读取这段数据，后续 256 KB 完整分段并行补齐。播放器索要文件尾或拖动位置时，按 256 KB 对齐获取远端 Range，校验 HTTP 状态、Content-Range、长度与实体标识后落盘。重新打开保留磁盘缓存，轮换 URL 查询 token 不重复下载。每个租约随播放器的 reset/release/交接一起释放。旧版 256 KB 分段继续兼容，首次未缓存播放最多多传输 64 KB 文件头。

后续分段使用官方 [`requestInStream`、`headersReceive`、`dataReceive`、`dataEnd`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-network-kit/js-apis-http.md) 流式接口。响应头确认 206、范围、长度和实体标识后，收到的 64 KB 数据块立即交给 AVPlayer，无需等满 256 KB。只有完整响应和最终状态校验通过才落盘；缺少 status-line 的响应会等最终状态确认再交付。截断传输仅重试一次，继续读取原有字节偏移，不重复交付已读前缀。流关闭会唤醒等待中的读取并释放下载位置，即使状态结果早于 dataEnd 返回也不会占住队列。

整个应用最多同时执行两个远端分段请求。当前流边发送边预取后续两段，以重叠网络往返等待；实际读取和拖动位置的请求优先于推测预取，前台优先于相邻视频预加载。已排队的预取被实际读取命中时会提升优先级。后台预加载只占一个空闲请求位置，视频流只预加载相邻一项。取消独立的整文件后台缓存下载，避免与当前播放竞争带宽。分段和旧完整文件共用约 200 MB 的容量预算，正在读取的分段受保护，长视频也会淘汰旧分段。CDN 不支持 Range 时保留原生 URL/代理完整文件回退。

共用流的优先级按租约计数：只要还有前台播放租约，后台预加载或暂停其中一个播放器不会把整个流降为后台。关闭的租约不能再次提升优先级。

自动清晰度参考同一个 CDN 最近 45 秒的前台传输速度，并为播放留出 30% 余量；小文件头、后台下载和缓存读取不参与测速。估算对降速反应快，对升速反应慢，不把手机链路的标称带宽直接当作视频服务器的实际速度。自动首播上限为 1.5 Mbps，实际下载更慢时进一步降低；手动高清、标清和流畅选择不经过这项上限。

清理视频缓存时先退役活跃流，当前播放器继续读取；最后一个租约关闭后删除文件。无效或过期的索引不会使旧分段重新有效。

视频页显示时暂停被覆盖的普通播放器，阻止首页可见性回调启动新流；退出后只恢复此前有播放意图且仍在可见范围内的播放器。视频页自己隐藏时停掉播放和预加载，继续保留播放器交接流程。队列执行前读取实时前后台优先级。完整文件与分段按访问时间一起淘汰，保护活跃 fd 和正在下载的文件，避免一个旧的大文件把新分段反复挤出缓存。

播放器的缩放、音量、倍速、seek 操作检查原生 `state`，仅在 prepared/playing/paused/completed 执行。提前发起的 seek 保留到 prepared；`videoSizeChange` 可能在 prepare 完成前上报，不应触发不允许的缩放操作。5400102 控制错误且原生未进入 error 状态时只记录，不丢弃有效缓存；真正的源错误仍触发重试或切换码率。完整文件损坏后同一源仅重试一次，避免循环下载。

连续切换清晰度时只执行一个原生 reset，完成后使用最后一次选择；旧播放源的租约保留到 reset/release 完成，旧回调不能关闭新源。遇到首帧超时或播放进度停滞时，保留已经校验过的缓存，先降到下一档更低码率；没有更低码率时仅重连一次。慢网络恢复不会反向升码率，也不会因为缓冲等待而清空缓存。

`VideoPlayerPreparation` 按 AVPlayer 共享正在执行的准备任务。首页播放器在 initialized/prepare 过程中交接到视频页时，新视图复用同一次 setPlaybackStrategy/prepare，不再次准备同一个原生播放器。绑定 surface 时读取原生 state；重置或释放会取消旧的准备续接。控制状态拒绝不会使有效缓存失效。交接后的首帧计时从接收播放器开始，预加载等待单独标记，避免产生包含上一条视频停留时间或零时间戳的错误指标。

原生 HTTP 解析错误触发回退时，先检查完整的已校验分段，齐全则用 64 KB 内存块合成临时 MP4，登记后通过 fdSrc 播放，避免重新下载。未完成、已退役、已关闭或超过容量预算的数据不能晋升为完整缓存；缓存清理期间的旧任务也不能把文件重新登记。复制时保护正在读取的分段，切源后的旧恢复结果不能重置新源。

本地 HTTP 响应使用 Content-Length 界定结束，并支持连接复用、分片请求头和连续请求。客户端主动要求关闭、传输失败或空闲 10 秒才关闭连接；保留每个流最多 6 个连接的限制。新增响应完成、失败、无效范围及连接超限日志，用于区分下载失败与原生解析失败。
