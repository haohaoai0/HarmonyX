# 支持者激活与恢复

## 绑定与恢复规则

卡密在 XXAuth 绑定的是 X 账号固定 `userId/rest_id`，不是用户名、物理设备、版本号或本地账号槽位。两个产品版本必须保持同一个 `XXAUTH_APP_ID`。X 的 Cookie、OAuth Token 不会传给 XXAuth。

| 场景 | 行为 |
| --- | --- |
| 应用内 A → B → A | 分别读取两个账号的凭证，切回 A 自动恢复 A 的本地状态；B 不继承 A 的资格 |
| 校验中切换账号 | 已发送的请求仍只保存到原账号；当前界面只发布当前账号状态，新账号独立校验 |
| 同一账号改用户名 | 固定用户 ID 不变，资格保留 |
| 同包名覆盖升级 | 自动读旧版 v1 数组，之后按账号逐条写入 v2 安全存储；离线时仍能读未过期旧记录 |
| Harmony X / Croak X 两个包名之间切换 | 安全存储隔离；登录同一 X 账号，重新输入原码，由同一云端绑定恢复 |
| 新设备、重装、清除数据 | 登录同一 X 账号后输入原码恢复，无需解绑物理设备 |
| 断网、限流、服务故障、在线数/IP/地区限制 | 保留本账号未过期缓存；下次前台轮询可重试，手动刷新可立即重试 |
| 云端明确停用、删除、到期或绑定已变更 | 只回收该卡原账号的记录；再次成功校验可恢复 |
| 安全存储暂时不可读 | 不把读取失败当成空记录、不覆盖旧数据，下次重试 |

当前云端提供的是卡密核验，并没有“仅凭已登录 X 账号自动找回卡密”的受信接口。无本地凭证时仍需要原码；单独公开一个按 `userId` 查询卡密的接口会泄露凭证，不能用来代替恢复流程。需要完全无感跨设备恢复时，应另建验证 X 账号归属的服务端权益接口。

## 客户端兜底

- 在首次异步读取前捕获提交账号；等待期间账号改变就取消尚未发送的激活，避免给新账号误绑。
- 只有同账号、同码的并发请求才合并；其他请求串行处理，排队期间退出或切到第三个账号会取消。
- 账号切换立即同步资格，不受推荐内容请求进行中的限制；界面用修订号丢弃旧请求的提示和加载状态，并清空输入框。
- 云端成功响应必须具有匹配的软件 ID、卡 ID、非空且匹配的账号绑定，以及可解析的未到期时间。缺失绑定会显示配置异常，不新增资格。
- HTTP 缓存关闭。自动校验成功后按账号限频 5 分钟，暂时失败不消耗这个成功限频；前台推荐宿主每分钟轮询。
- `harmonyx_supporter_account_v2_<userId>` 每条只保存一个账号，避免旧版 4 账号淘汰和多个长码合计超过 Asset Store 单条 1024 字节上限。旧 `harmonyx_supporter_v1` 保留作兼容读取，已写入的 v2 记录优先，包含停用记录。
- 明确回收先更新内存再写盘。若安全存储写入失败，本次进程仍会回收并显示存储错误；此时无法保证重启后的离线持久化，恢复存储后必须重新在线核验。
- 未过期缓存允许离线使用；过期不延长。系统时间明显倒退超过 5 分钟时不直接信任旧校验时间。
- 不会更改云端绑定以让另一个 X 账号继承原码；应用内切号无需调用解绑。

## 云端配置核对

2026-10-20 直连 `https://api.xxauth.com/open/v1` 读取当前应用：

- 软件 ID 与客户端 `2778143c-260a-4e04-83ad-2889f6aaad0d` 一致。
- `auth.bind_machine="true"`，保持账号绑定。当前 `login_mode="free"`，不要为了可选免推荐资格把整个免费应用改成强制收费登录。
- `security.heartbeat_interval=30`、`heartbeat_timeout=90`，`heartbeat_verify_machine=false`、`heartbeat_verify_ip=false`。客户端只用登录核验免推荐资格，不维持受保护内容接口的在线会话；未来若接入需心跳的权益接口，必须另接该心跳协议。
- `limit`、`unbind` 返回空对象，表示未显式公开配置，不能声称已经验证了默认在线数或所有迁移限制。避免绑定首登 IP、按登录扣点或以物理设备为依据的限制，否则换网络/设备可能被拒绝。
- 随机构造的无效测试码直连 `/card/login` 返回 HTTP 404、`卡密不存在`。没有使用、激活或重绑真实卡密。

读取结果在 `outputs/supporter-cloud-audit-20261020.json`。云端未来变更仍应再次读取验证。

Asset Store 容量依据：[华为敏感数据保护文档](https://developer.huawei.com/consumer/en/doc/harmonyos-guides-V14/asset-scenario1-V14)。接口与错误码同时核对本地 SDK `@ohos.security.asset.d.ts`，HTTP 禁用缓存参数核对 `@ohos.net.http.d.ts`。

## 验证边界

自动化执行真实服务源码，模拟 Asset Store、HTTP 和账号状态，覆盖多账号异步竞态、账号独立限频、8 个长码账号重启恢复、旧数据迁移、停用覆盖旧缓存、存储读写失败及错误分类。

命令：`node --test tests/xxauth-supporter.test.cjs tests/xxauth-popup.test.cjs tests/xxauth-promotion-post.test.cjs tests/xxauth-recommendation.test.cjs tests/home-tab-feed-regression.test.cjs tests/settings-catalog.test.cjs`。

本次结果：28 项激活用例和 63 项关联回归通过；Croak-X 同一组 91 项用例全部通过。两版 `devecocli build --modules entry` 均成功，X-new 为签名包并已在 Mate 80 Pro Max 覆盖安装、启动；Croak-X 当前构建未配置签名，只确认编译及打包，不作为可安装包验收。本次没有完成真机激活页及多账号切换的交互验收。

模拟的新设备/新包名恢复不等同于两台设备的真实卡密验收；跨设备、两个产品版本及云端停用对照仍应使用测试账号与可用测试码完成实机验收。降级到不认识 v2 存储的旧二进制也不能保证离线恢复，需在线重验。
